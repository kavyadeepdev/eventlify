# Eventlify - System Architecture Specification

This document details the software architecture, domain routing setup, database extensions, BaaS infrastructure, dynamic permission system, and AI microservice integration for **Eventlify**.

---

## 1. Subdomain & Routing Architecture

Eventlify uses Next.js 16 (App Router) `middleware.ts` to inspect the incoming `Host` header and route requests dynamically to dedicated persona portals.

```
                                +-----------------------------------+
                                |     Next.js 16 App Router         |
                                |     (middleware.ts Router)        |
                                +-----------------------------------+
                                                  |
           +--------------------------------------+--------------------------------------+
           |                                      |                                      |
           v                                      v                                      v
  [ eventlify.in ]                     [ club.eventlify.in ]                  [ admin.eventlify.in ]
  Public Student Portal                 Club Management Portal                 Platform Admin Panel
```

### Domain Routing Table

| Subdomain | Internal Route | Primary Responsibility | Target Persona |
| :--- | :--- | :--- | :--- |
| `eventlify.in` | `/` | Public event discovery, solo/team registration, student ticket wallet, club directory. | Students & Public |
| `club.eventlify.in` | `/club/*` | Club management dashboard, event publishing, payment verification queue, custom roles, BaaS keys. | Club Officers & Admins |
| `admin.eventlify.in` | `/admin/*` | Platform control center, club onboarding approval queue, global event moderation, user system role management. | Platform Super Admins |

## 2. Database Schema Extensions

### 2.1 Dynamic Club Roles (`club_roles` & `club_member_roles`)
Clubs configure custom roles (like Discord server roles) with rank hierarchies, custom HEX colors, and granular permission flags.

```dbml
club_roles {
  id string pk
  club_id string fk -> clubs.id
  name string             // e.g. "President", "Tech Lead", "Event Manager"
  color string            // e.g. "#FF5733"
  rank number             // Hierarchy rank (1 = highest)
  permissions jsonb       // Array of granted permission flags
  created_at timestamp
  updated_at timestamp
}

club_member_roles {
  club_id string fk -> clubs.id
  user_id string fk -> users.id
  role_id string fk -> club_roles.id
}
```

### 2.2 System & Permission Flags
- `MANAGE_CLUB`: Edit club profile, logo, banner, social links, contacts.
- `MANAGE_ROLES`: Create, reorder, colorize, and assign custom club roles.
- `MANAGE_MEMBERS`: Add/remove members, assign custom roles.
- `MANAGE_EVENTS`: Create, edit, publish, and delete events.
- `MANAGE_ATTENDANCE`: Conduct door check-in, verify payment proofs, export attendee CSV.
- `MANAGE_API_KEYS`: Configure BaaS CORS allowed origins and generate external API keys.

### 2.3 Onboarding & Status Extensions (`club_applications`)
```dbml
club_applications {
  id string pk
  applicant_id string fk -> users.id
  name string
  slug string unique
  category string
  description string
  logo string
  contact_email string
  contact_phone string
  status string           // 'PENDING', 'APPROVED', 'REJECTED'
  rejection_reason string
  reviewed_by string fk -> users.id
  reviewed_at timestamp
  created_at timestamp
  updated_at timestamp
}
```

### 2.4 Payment Verification Extensions (`events` & `registrations`)
- `events`: `is_paid` (boolean), `fee_amount` (numeric), `upi_id` (text), `upi_qr_url` (text).
- `registrations`: `status` ('CONFIRMED', 'PENDING_VERIFICATION', 'APPROVED', 'REJECTED'), `payment_proof_url` (text), `transaction_id` (text), `rejection_reason` (text), `verified_by` (uuid), `verified_at` (timestamp).

## 3. Backend as a Service (BaaS) & CORS Control

Eventlify acts as a single source of truth database for clubs running external custom websites (e.g. `https://acm-bmsce.in`).

### Public API Architecture (`/api/v1/public/*`)
- `GET /api/v1/public/club` — Returns club profile, verified members, social links.
- `GET /api/v1/public/events` — Returns active/upcoming events, schedules, banner URLs.
- `GET /api/v1/public/events/[slug]` — Returns specific event details and constraints.

### API Key & Origin Security
- **API Keys (`club_api_keys`):** Scoped key `ev_live_...` generated by Club Admin.
- **CORS Validation:** `allowed_origins` stored in database (e.g. `["https://acm-bmsce.in"]`). Requests without a valid origin match are blocked with HTTP `403 Forbidden`.

## 4. Python AI Microservice Architecture (`eventlify-ai-service`)

The AI features run in a dedicated, independently deployed Python FastAPI repository.

```
   +-----------------------+              HTTP / Webhooks             +----------------------------------+
   |   Next.js App Router  |  ------------------------------------->  | Python FastAPI AI Microservice   |
   | (eventlify monorepo)  |                                          |     (eventlify-ai-service)       |
   +-----------------------+  <-------------------------------------  +----------------------------------+
                                     Signed JWT / Internal Key                     |
                                                                                   +--> 1. OCR (ID Card Scanner)
                                                                                   +--> 2. Certificate Engine (PDF/PNG)
                                                                                   +--> 3. LLM Structured Ingestion Agent
```

### Microservice Modules:
1. **Student ID Card OCR Scanner (`/ai/ocr/scan-id`):**
   - OpenCV boundary crop & contrast thresholding.
   - EasyOCR / Tesseract extraction for USN, Name, Department, and cropped PFP.
2. **Dynamic Certificate Generator (`/ai/certificates/generate`):**
   - ReportLab / Pillow vector PDF & PNG certificate generation.
   - Embeds student details, event badges, and cryptographic verification QR codes.
3. **Conversational LLM Ingestion Agent (`/ai/ingest/parse`):**
   - Parses unstructured raw text (WhatsApp event copy, flyers, officer lists) into validated JSON schemas using Gemini / OpenAI for 1-click database insertion.
